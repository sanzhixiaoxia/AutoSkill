# 路由细则与边界判定

`../SKILL.md` 给的是主流程与方向→检索词参考；本文件补充"看起来很像但其实该走不同路子"的判定、常见组合编排，以及缺能力时的退路。只在拿不准时按需查阅。本文同样不预设固定能力清单、不绑定具体平台——能力以宿主注入清单与分层检索结果（已装本地 → 优质平台 → 其他远端 → 通用工具，本地优先、网上补足）为准。

## 一、易混场景对照

下表用"意图特征"区分，不写死具体能力名——两侧的判定依据是"产物形态 / 是否需要外部系统 / 是否面向平台发布"，落到具体能力时以当前可用清单或平台检索为准。

| 请求长这样 | 该走的方向特征 | 不要走（易误判） |
| --- | --- | --- |
| "在对话里画个关系图/流程图" | 对话内图形渲染 | 不要调生图类能力——对话内图形不是图片文件 |
| "生成一张海报/封面图（要文件）" | 图像生成，产出图片文件 | 不要用 HTML/CSS 截图替代 |
| "把图里的人/物抠出来" | 图像主体提取 | 不是常规改图/生图 |
| "读一下这个网页讲什么（只要正文文字）" | 纯文本抓取（通用工具即可） | 只有需要交互/渲染/登录才走浏览器自动化 |
| "登录某站点、点按钮、抓渲染后的内容" | 浏览器自动化 | 不要用纯文本抓取反复试 |
| "总结这个视频链接" | 视频链接理解 | 与"把文稿做成视频"（产视频）区分开 |
| "把这段文案读出来" | 文字转语音 | 不是语音转文字（转写/字幕） |
| "做一份调研报告" | 深度调研（再据形态出稿） | 若只是"解释一个概念"，直接答即可 |
| "帮我做个记账 APP/小程序" | 可运行应用的构建 | 若是"设计一个页面原型/官网稿"，走界面设计方向 |
| "页面/官网/后台/仪表盘设计" | 界面与前端设计（通常是套件） | 与"构建可运行应用"区分：前者只要设计稿 |
| "验收 / 上线前检查" | 项目验收 | 不要用普通代码检查糊弄 |
| "写篇小红书笔记 / 公众号文章 / 抖音脚本" | 面向平台发布的内容（自媒体套件） | 与通用长文创作区分：面向平台发布的走自媒体方向 |
| "写小说 / 故事 / 作文 / 儿童读物" | 通用长文创作 | 面向平台发布的营销/笔记不归此方向 |
| "订酒店 / 机票 / 做行程" | 出行旅行 | 单纯问"某地天气/位置"走地图位置方向 |
| "查股票/基金/持仓/财报" | 金融投资 | 普通公司介绍不算 |
| "580 分能上什么学校 / 志愿填报" | 高考升学 | 与考研/留学等非高考场景区分 |
| "某名词是什么意思" | 直接答；需权威词条时走百科方向 | 一步可答的常识不必动用能力 |
| "帮我做份简历 / 准备面试" | 求职 | — |
| "帮我找/装/做一个技能" | 技能检索 / 安装 / 创建 | 创建走创建能力，查找安装走检索能力 |
| 准备用 `![](URL)` 贴图 | 图片链接校验 | 任何贴图前都应先校验 |

## 二、常见组合编排（按依赖顺序）

- **调研 → 成稿**：先出调研材料，再按目标形态出稿（文档 / PDF / 演示）；若要求图表，叠加可视化方向。
- **数据处理 → 可视化**：先整理表格数据，再出图（若需以图片交付，再走图像生成方向）。
- **应用构建 → 验收**：先产出可运行应用，再做项目验收。
- **设计 → 落地**：先出页面设计，若要变成可运行应用，再走应用构建方向。
- **自媒体内容链**：选题 → 写作 → 数据复盘；需要配图/封面时转接图像生成方向。
- **跨域并行的请求**（如"整理这份表格，再写一段总结"）能并行就并行，不要串行等待。

## 三、缺失能力与分层降级

宿主注入清单里没有合理匹配时，把意图方向转成 2–3 个检索词，交给 `scripts/search_skill_platform.py`，**由脚本按下面的顺序逐层尝试，命中即停**（无需你手工逐层找）：

1. **已装本地能力**（`local_installed`，离线扫描本机已装 skill / 套件）——首选：离线、最快，本机已有的能力拿来就用、无需安装。注意本地层的对口判定比远端严（整词命中或 ≥2 个实词重合），弱相关的已装条目不会挡住远端；"做份简历"这类动词+核心词的检索词没命中本地属正常，落到远端找即可。
2. **优质平台**（`quality_platform`，skill 技能平台 / hub）——本地没有对口的，才上网到这里找。
3. **其他远端来源**（`other_remote`，如技能广场）——优质平台也没有时，再降一级。
4. **SkillHub 开放社区**（`skillhub`，api.skillhub.cn 免鉴权检索 + `skillhub` CLI 安装）——不依赖宿主检索入口；宿主入口缺失或上述远端全部失败时，这层仍可触达远端并给出可安装候选。
5. **通用工具**（`generic_tools`）——以上都没有对口项时，用通用工具（Bash / 文件工具 / 纯文本抓取 / 搜索等）兜底，并向用户说明这是通用路径而非专用能力。

返回里的 `active_layer` 告诉你最终命中了哪一层，`layers` 里每层的 `status` / `kept` / `errors` 说明各层实际发生了什么；不要只看最终候选、忽略是哪一层给的。

**命中平台候选后的安装：先展示、确认后执行。** 先向用户展示候选的**来源、名称、版本、下载地址与哈希情况**并取得明确同意，然后两段式执行（候选里的 `install_hint` 是现成参数，已含版本）：

```bash
# 1) 预览（默认行为）：策略校验 + 返回 confirm（来源/版本/下载地址/将执行的命令）
python3 scripts/search_skill_platform.py install --slug <slug> --source hub --download-url "<url>" --version <v>
# 2) 用户明确同意后，原命令加 --yes 才真正执行
python3 scripts/search_skill_platform.py install --slug <slug> --source hub --download-url "<url>" --version <v> --yes
# 重新启用：台账外（可能被用户有意禁用的）候选需 --user-confirmed
python3 scripts/search_skill_platform.py enable --slug <slug> --yes
```

策略由脚本强制：下载地址须过**域名白名单**且为 https（`SKILL_INSTALL_ALLOWED_HOSTS` 可配置）、**版本须固定**（缺失需用户知情加 `--allow-unpinned`）、提供 `--sha256` 时先下载校验再以本地文件安装、无哈希需 `--allow-no-hash` 知情豁免；`--force` 仅随确认生效；`enable` 不覆盖用户此前的禁用决定。退出码 `0` 表示跑通（预览也算），`2` 表示被策略拦下或安装失败/超时——策略拦下时读 `error` 字段，换候选或退回上一层。调用契约与审计入口见 `installer-contract.md`。

**首次调用前披露数据范围。** 新装能力首次执行前，向用户说明它将接收哪些用户数据（对话内容、文件与路径、链接、可能的凭据等），用户有权拒绝；拒绝则不调用，改走通用工具或既有能力。披露只需一次，后续不重复盘问。

**候选质量：**脚本默认已做**噪声过滤**——剔掉占位/测试名、纯数字纯符号名等无信息量条目，以及只靠"生成""工具""设计"等泛词蹭到的弱相关条目；过滤统计见 `filter` 字段。所以正常拿到的候选已经是清洗过的，直接判对口即可；想核对原始返回再加 `--no-filter`。

**仍无合适能力、又不值得新建时**，用通用工具兜底；**用户确实需要新能力时**，转 `skill-creator` 创建技能，或 `plugin-creator` 创建套件。

> 检索失败 ≠ 平台没有该能力。入口缺失、网络或鉴权失败会被脚本记进 `errors` 并继续降到下一层，向用户如实说明失败原因，不得把失败当成"没有匹配"。

## 四、灰区怎么定

- 判不准"要不要动用专门能力"：倾向动用——多查一次的成本通常低于漏用。
- 判不准"走哪个方向"：能给出一句说得通的理由就按该方向做，并在开工说明里点明；只有当两个方向会导致明显不同的交付物、且用户意图确实不明时，才用 `question` 问一次。
- 判不准"用户想要文件还是要对话内结果"：默认按能直接满足使用的方式给（要留存/分发→出文件；只是看看→对话内呈现），并在交付时说明。
- 判断错了要能纠偏：如果执行中发现方向不对，就地切换并说明原因，不要把错路走完。
